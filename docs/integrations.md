# Integrations

The product scope includes Postfix, Dovecot, spam-filtering services, ClamAV,
DKIM signing, databases, and DNS. The server detects an allow-list of mail
components and can inspect or operate supported services through the host's
service manager. Supported package-name mappings cover Alpine, Debian-family,
RHEL-family, and FreeBSD systems; service control returns an explicit error
when the host lacks a supported manager or component.

Operator-authenticated APIs currently manage virtual mailboxes and passwords,
domains and DNS/DKIM records, aliases, forwarding rules, and Postfix queue
entries. Mail records are persisted in the database and assigned to the
reserved `system` owner. DKIM private keys are encrypted at rest. Queue
mutations call installed Postfix commands and require the server process to
have the necessary operating-system permissions. These database operations do
not yet synchronize configuration into a running MTA. Unix mail-account management,
transport rules, spam/virus integration, certificate management, log
management, and delivery-statistic ingestion remain unavailable.

The public web shell serves Swagger UI at `/server/docs/swagger`, GraphiQL at
`/server/docs/graphql`, and the Streamable HTTP MCP endpoint at
`/api/v1/server/mcp` (with `/api/mcp` and `/mcp` aliases). MCP requires a valid
Bearer token and filters registered tools by authorization tier. Owner tokens
have no access to the globally operator-managed mail records. The shell also
serves a server-rendered connection guide at `/server/help/mcp` and its JSON
mirror at `/api/v1/server/help/mcp`. The guide lists live tools available to a
standard token; the operator token also sees mail-management tools. Project
guidance is configurable with `server.pages.help.mcp`. The shell serves a PWA
manifest at `/manifest.json` and a service worker at `/sw.js`. It caches only
server-marked public pages for offline use and synthesizes a translated offline
page; there is no standalone `/offline.html` resource. No
mail-service webhook, identity provider, federation, or optional protocol
discovery integration is enabled yet. Public `security.txt` and `llms.txt`
resources are generated by the server; optional federation and identity
metadata endpoints remain disabled.

The scheduler has persistent task definitions and execution history, catch-up
handling, and a configurable timezone and per-task schedules. Database and
self-health probes run, and token cleanup removes expired CAPTCHA challenges
from `server.db`. CAPTCHA issuance and verification, including simple,
reCAPTCHA, and hCaptcha flows, are not yet implemented. Backup, GeoIP,
certificate, log-rotation, and other scheduled maintenance providers are
unavailable; see the project backlog for the current inventory.
